# Windows 窗口截图

截运行中的程序窗口，输出与肉眼所见一致的 PNG：含标题栏与状态栏，无黑边，不受其他窗口遮挡影响。

## 用法

```
cd <本技能>/scripts
./window-shot.exe <进程名或PID> <输出png路径> [-click <按钮文字>] [-select <列表项文字>] [-mouse X,Y] [-wait <毫秒>]
```

```
./window-shot.exe WinTray.exe "image/01.png"                                  # 直接截当前界面
./window-shot.exe WinTray.exe "image/01.png" -select "netmount"               # 先选中列表里这一项
./window-shot.exe WinTray.exe "image/02.png" -click "更多功能"                # 先点按钮切页
./window-shot.exe WinTray.exe "image/02.png" -mouse 2510,336                  # 自绘界面：按屏幕坐标点
```

| 开关 | 用途 | 取值 |
| --- | --- | --- |
| `-click <文字>` | 点原生按钮（`BM_CLICK`），用来切页/展开 | 按钮文字，先精确后唯一包含 |
| `-select <文字>` | 选中原生列表（ListView）的某一行 | 第 1 列文字，先精确后唯一包含 |
| `-mouse X,Y` | 点自绘界面（没有原生控件） | **屏幕**绝对坐标，可用 `-mouse` 前的截图量出 |
| `-wait <毫秒>` | 操作后等界面重绘 | 默认 800 |

三者可组合，执行顺序固定为 `-mouse` / `-click` → `-select`：先切页，再选行。

输出尺寸 = 窗口可见区域的物理像素，可直接用于文档、商店页、发布说明。

## 自绘界面只能按坐标点（`-mouse`）

有些程序（如用 `github.com/egoist/mygo` 这类自绘库写的界面）窗口里没有原生控件，按钮和列表都是画出来的，`-click` / `-select` 找不到东西。这时按坐标点：

1. 先普通截一张图，图里量出目标控件的像素位置。
2. 用 `./zoom-grid.exe <图> <输出图> <x> <y> <宽> <高> <放大倍数>` 放大该区域并叠加网格（每 10px 浅红、每 50px 蓝），鼠标位置一目了然。
3. 换算成屏幕坐标：工具每次截图都会打印 `图像左上角 = 屏幕 (X,Y)`，屏幕坐标 = 左上角 + 图内坐标。
4. 用 `-mouse X,Y` 点它，再截图确认落点正确（点错会直接在图上看出来）。

坐标不必精确到像素，落在控件内即可（按钮通常几十像素高）。

## 截图必须让界面静止

截图前工具会自动做两件事，不需要传参数：

1. **清掉控件焦点**。程序常自己给控件设焦点（例如切页后聚焦首个按钮、列表获得焦点），会画出焦点虚线框、输入框光标。工具用 `AttachThreadInput` + `SetFocus` 把焦点移回窗口本身，并复查确认；清不掉时打印警告，不假装成功。自绘界面会拿一个铺满窗口的画布子窗口收键盘输入，这种情况只提示不影响截图。
2. **把鼠标挪到窗口外**，截图后还原原位。指针压在按钮上会留下悬停高亮，看起来像刚被点过。窗口铺满屏幕时无处可挪，会提示。

所以优先用 `-click` / `-select`（消息驱动，不产生按下、悬停、焦点痕迹）；只有自绘界面才用 `-mouse`，此时真鼠标点击的痕迹由上面的「挪开鼠标」负责清掉。

## 步骤

1. **确认窗口可见**。`PowerShell: (Get-Process <名字>).MainWindowHandle`，返回 0 说明窗口没显示，直接截会报「没有可见的主窗口」。
2. **让窗口显示出来**（窗口不可见时才需要，别杀进程）
   - 只在托盘：**再启动一次该程序的 exe**，多数程序有单实例逻辑，会激活已有实例把窗口显示出来。
   - 最小化：不用管，工具会自动还原。
   - 仍不行：手动点托盘图标或任务栏图标。
3. **截图**：执行上面的命令；需要切页加 `-click`（自绘界面用 `-mouse`），需要选中再加 `-select`。
4. **验证**：`./check-edges.exe <png>`，四边黑边须全为 0；再看图确认三件事：标题栏与底部状态栏等内容完整、确实是目标页面、**没有焦点虚线框/按钮悬停高亮/输入框光标**。
5. **交付**：把 PNG 放到用户指定位置，同时用图片预览确认内容无误。

## 关键约束

- 抓窗口用 **PrintWindow(PW_RENDERFULLCONTENT)**，不用屏幕截屏。从命令行执行时控制台窗口常压在前台，屏幕截屏会把控制台一起抓进去。
- 进程必须先 `SetProcessDPIAware()`。否则高缩放屏幕上 `GetWindowRect` 返回逻辑坐标，截图会被裁切。
- **黑边来自 Windows 的不可见调整边框**：Win10/11 的窗口矩形比可见窗口每边大 7~8px，PrintWindow 把这一圈画成纯黑。工具用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 取可见框裁切，再用采样探测黑边收尾（DWM 边界实测仍差 1~2px）。
- **切页优先给按钮发 `BM_CLICK`**，不模拟鼠标：不要求窗口在前台、不受遮挡影响，也不用算坐标。只匹配 `Button` 类控件，避免点到同名标签。按钮文字匹配先精确、后唯一包含（`← 返回`、`删除…` 这类装饰文字不影响 `-click "返回"` 命中），多候选时报错不猜。
- **选中列表项用键盘**（HOME + N×DOWN）而不是 `LVM_SETITEMSTATE`：后者直接改控件状态，可能不触发程序自己的选中回调，右侧详情就不刷新。要知道点第几行，工具跨进程读出列表文字（`LVM_GETITEMTEXTW` 需在目标进程里分配缓冲区），并按文字匹配、回读确认。
- `-mouse` 需要窗口在前台，工具会先用 `AttachThreadInput` 挂接输入队列把窗口切到前台；仍失败才提示点击可能落空。
- **不按窗口标题/类名匹配窗口**：标题随语言变化，类名是实现的内部细节。工具按「同 PID + 可见 + 无 owner（排除对话框）+ 有标题栏」筛选，取面积最大者。
- 一个程序有多个同名进程时，取「有可见窗口且面积最大」的那个；多窗口程序想截特定窗口，改用 PID 并确保目标窗口在最前。
- 截图会顺带把目标窗口还原、置前、清焦点并挪开鼠标，属预期副作用；鼠标位置会自动还原。
- 工具每次会打印 `图像左上角 = 屏幕 (X,Y)`、窗口矩形、可见框与黑边裁剪量，这些是换算坐标和排查问题的依据，别丢。
- 用户的界面状态（选中的行、填好的输入框）会照原样拍进去，不是残留；只有焦点、悬停、按下这类瞬时装饰才算残留。**要保住某个选中状态就别去改它**，截图本身不会动选中项。

## 文件

| 文件 | 作用 |
| --- | --- |
| `scripts/window-shot.exe` | 截图主工具 |
| `scripts/window-shot.go` | 主工具源码（纯 stdlib + syscall，无第三方依赖） |
| `scripts/check-edges.exe` / `.go` | 检查 PNG 四边黑边厚度并打印四角像素值，用于验证 |
| `scripts/zoom-grid.exe` / `.go` | 放大指定区域并叠加网格，用于量出自绘界面控件的坐标 |
| `scripts/build.sh` | 重新构建全部 exe（需要 Go） |

## 重建

```
bash scripts/build.sh
```

脚本先找 PATH 里的 `go`，找不到则回退到 `$USERPROFILE/sdk/go*/bin/go.exe`。三个工具都是单文件 main 包，用单文件构建（file-based build），不需要 go.mod。
