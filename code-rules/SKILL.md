# 代码工作约定

- 先读相关实现和调用方，按影响范围调查；共享接口或来源不明时扩大搜索，不为小改动扫描全库。
- 优先修改已有控制点，复用共享的解析、验证和安全逻辑。保持清晰职责，不因行数机械拆分，也不顺带大规模重写。
- 修复根因并覆盖同类输入，不为单个样本硬编码；不添加静默降级、吞错或假成功旁路。
- 保护用户已有改动；同步受影响的接口、引用和必要产物。检查差异，避免无关格式或编码变动。
- 用可观察行为验证：故障可复现时加入回归测试，兼容性修复覆盖失败样本、同类输入和正常输入。配置、文案等选择相称检查，不为流程删除已完成实现。
- 测试公开行为、输出或产物，避免用源码文字匹配代替行为测试，除非文字本身就是契约。
- 完成实现后运行必要流程、检查结果、修复本次失败并复验。证据对应当前文件及相关环境；未变化时不因换一条回复重复执行。
- 构建只证明可构建，测试只证明已测行为，差异只证明改动范围。无法验证的部分明确说明，不能宣称已完成。
- 用户要求完整交付时给出可用的完整文件，不用占位符代替必要内容；长产物写文件，不机械等待“继续”。

专项清单审查时读取 [review-checklist.md](references/review-checklist.md)，普通编码不额外加载。
