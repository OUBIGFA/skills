# Target Scope Verification

## Purpose
在查询任务中防止目标错配、范围漂移和证据不足却给出确定结论。

## When to Use
当请求包含以下任一意图时触发：
- 查询某对象的资源位置
- 核对是否存在某类配置或扩展
- 对比多个位置的内容并给结论
- 刚完成安装/迁移后，立即进行关联查询

## Mandatory Workflow
1. 目标锁定
   - 先用一句话复述“本次要查的目标对象”。
   - 同时声明“本次排除范围”。

2. 分层检查
   - 按固定层级检查，不跳步：运行时位置 → 用户配置位置 → 安装位置 → 通用资源位置。

3. 证据归档
   - 输出必须包含：
     - 实际检查位置
     - 命中项名称
     - 命中对象类型（真实项/链接项）

4. 结论门槛
   - 证据完整：可给“已确认”。
   - 证据不完整：只能给“未确认”，并附下一步验证动作。

5. 表述规范
   - 默认使用通用措辞。
   - 未经明确要求，不使用具体产品名、品牌名、路径名、一次性案例。

- 目标范围：
- 排除范围：
- 检查层级与位置：
- 命中结果：
- 证据完整性：完整 / 不完整
- 结论：已确认 / 未确认
- 下一步：
