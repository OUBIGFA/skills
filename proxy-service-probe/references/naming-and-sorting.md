# 打标、编号与排序规则

本文件承接 `SKILL.md` 的命名契约细节。标签判据（测速、免盾、AI、信誉）见 [testing-criteria.md](testing-criteria.md)，属地认定见 [geolocation.md](geolocation.md)，策略组成员见 [config-rendering.md](config-rendering.md)。实现以 `scripts/core/tagger.py` 与 `scripts/core/renderer.py` 为准。

## 1. 命名结构

```text
[国旗] [✨️] [🏠 / ♥️] [❇️] [Key / Free / Fast] [国家][_城市]_[编号][_IPLC 或 _ISP][落地后缀][流媒体后缀][来源后缀][污染标记]
```

- 前缀徽章顺序固定：✨️ > 🏠 / ♥️ > ❇️ > Key / Free / Fast。
- 后缀只用英文缩写：`_IPLC`、`_ISP`、`_Lnd`、`_USAI`、`_GOAI`、`_NF`、`_D+`；不保留“HiNet家宽”“双ISP”“Seller双ISP”等中缀。
- 污染标记如 `_⚠️CN`、`[⚡WARP]` 放在最后（其中 `_⚠️` 送中/地区污染剥夺 `❇️`/`✨️`/`_USAI`/`_GOAI`/`♥️`/`🏠`；而 `[⚡WARP]` 套壳标记**保留 AI 解锁标记 `❇️`/`_USAI`/`_GOAI`**，仅剥夺 `🏠`/`♥️`/`✨️`/`_ISP`）。

## 2. 前缀徽章

| 徽章 | 授予条件 | 互斥与剥离 |
|---|---|---|
| `✨️` | AI 全通 + Groq + YouTube 免登实播 + WAF 免盾分数与直通站数达标 + 丢包率达标（阈值以代码为准） | 中度丢包、送中/受限污染或 `[⚡WARP]` 套壳时剥离 |
| `🏠` | 真实网络层检测为 Level 1 原生家宽（严禁采信上游节点名自标家宽），且综合信誉达标、无 cf-mitigated 硬拦截、出口稳定无污染 | 与 ♥️ 互斥；Level 1 但信誉未达标改为 `_ISP` 后缀；不参与 `Key` 评选 |
| `♥️` | 非家宽节点，综合信誉达标、无 cf-mitigated 硬拦截、出口稳定 | Level 3 住宅代理池、带 `_⚠️CN` 或 `[⚡WARP]` 等污染标记不授予 |
| `❇️` | OpenAI + Claude + Gemini + Hugging Face + Grok 全通，出口稳定非送中 | OpenAI Sentinel 判定重度降智（`DEGRADED_HEAVY`）或 `_⚠️` 送中污染时剥离（`[⚡WARP]` 保留 `❇️`） |
| `Key` | 通过 Key 准入（见下节） | 与 Fast、`🏠` 互斥 |
| `Free` | 带 `_USAI` 的美国 Key 节点改用 Free，排序与入组权重与 Key 完全相同 | 其他美国 Key 与非美 Key 仍用 Key |
| `Fast` | 主动完整测速达标（稳态与最低速率达标，阈值以代码为准）但未选为 Key/Free | 防断流快检、未测速、未达标均不授予 |

## 3. Key 准入

- 协议：禁止 `http`、`https`、`socks`、`socks5`。
- 拓扑：落地节点（`_Lnd`、需前置的 `_USAI` / `_GOAI`、实测经前置连通者）不可作 Key / Front。
- 家宽保护：真家宽节点（`🏠`）专作终端高纯净出口，不参与 Key 前置跳板评选。
- 出口：真实出网，且不与本机跑机基线 IP 重合。
- 测速：必须主动完整测速达标。
- 丢包：丢包率低于 `--key-max-loss-rate` 阈值（以代码默认值为准）。
- 评分与配额：按协议安全等级 + 高速直连核心区首选（`HK/TW/JP/SG` 最高加权，次级亚太 `KR` 次之）+ 速度 + 延迟 + 低丢包加权打分，并按代码默认单国配额上限选取（实现见 `scripts/core/key_evaluator.py`）。

## 4. 后缀

- `_IPLC`：节点名含 IPLC/专线标识时保留，排在所有后缀第一位（如 `🇭🇰 ❇️香港_1_IPLC_NF`）。
- `_ISP`：真实网络层检测为 Level 2 商用双 ISP，或 Level 1 但信誉未达 `🏠` 门槛的家宽（绝不因上游节点原名含“双ISP/家宽”而直接授予）。家宽又是专线时只留 `_IPLC`。
- `_USAI`：最终多数决归属美国且 AI 全通（`❇️`），即使多源存在分歧也不替换为 `_GOAI`。
- `_GOAI`：最终多数决归属**不是美国**，但谷歌认定为美国且具备原 USAI 能力（AI 全通 `❇️`），一律用 `_GOAI` 替换 `_USAI`。既非最终归属美国又非谷歌认定美国、或无 AI 能力的节点，两者都不授予。
- `_Lnd`：常规中转落地节点（仅经前置连通时保留；**任何测试中实测直连连通的节点一律移除 `_Lnd`/`_lnd` 后缀与 `dialer-proxy`**）。
- **以最新实测为准更新前缀/后缀**：每次测试后（无论全量测试、只测活或单项测试），均以本次最新实测结果为准更新对应前缀或后缀（如直连/落地状态变化、服务/速度/属地变化），不保留与最新实测相冲突的旧标记。
- `_NF` / `_D+`：Netflix / Disney+ 解锁。

## 5. 落地沉底例外

- 真正沉底并注入 `dialer-proxy` 的只有链式落地：`_Lnd`，或实测经前置连通的 `_USAI` / `_GOAI`。
- 直连 `_USAI` / `_GOAI`（无 `_Lnd` 且直连连通）不沉底、不注入 `dialer-proxy`，在主排序池按能力正常排位。
- 带 🏠 或 `_ISP` 的家宽节点即使带落地后缀或 dialer-proxy，也不沉底，始终留在主排序池。

## 6. 默认编号（不传 `--resort`）

- 本技能规范命名的原节点，属地未变则保留编号；服务结果变化只更新徽章与后缀。
- 新节点、属地已变化的节点按国家补最小空号，不挤占原编号；属地统一认定的新节点先于属地分歧的新节点分配。
- 地区顺序：亚太高速直连核心与已知国家/地区（`HK -> TW -> MO -> JP -> SG -> KR -> US -> ...`）→ 中国 → 未知。同地区内直连（含家宽）在前、链式落地沉底，其余按编号升序，不做能力重排。

## 7. 重排序与重编号（仅 `--resort` / 合流 `--insert`）

先定位置，再从 1 连续编号，不改前缀与后缀：

1. 同地区分为主排序池（直连 + 🏠/`_ISP` 家宽）与普通机房链式落地池，后者置于地区末尾。
2. 两个池内，属地统一认定的节点都整体排在属地分歧节点之前，不论服务能力。
3. 主排序池按 ✨️ > 🏠 > ❇️ > Key/Free > Fast；`_IPLC` 与家宽共享线路优先权（`line_prio = 0`），同级前缀内优先于普通机房节点。
4. 🏠 与 `_ISP` 节点内部保持原顺序（原编号/出现位次），不被延迟、测速或流媒体打乱。
5. 普通机房节点再按 `_NF` > `_D+` > 纯净优于污染 > ♥️ > 信誉分；♥️ 只在标签完全相同的节点之间生效，未知信誉排在有证据节点之后。
6. 信誉不跨越地区、落地沉底或 Key/Fast/能力硬规则。

## 8. 合流并入（`--merge-into` / `merge_configs.py`）

- 默认：保留底库原节点及原编号，新节点按国家补空号，并按标准地区聚拢。
- `--insert`（或 `--resort`）：打破原编号，按第 7 节完整重排并从 1 连续编号。

## 9. 示例

- `🇯🇵 ✨️♥️❇️Key日本_1_NF`：综合全通、高信誉、AI 全通、Key 前置、奈飞。
- `🇹🇼 ✨️🏠Fast台湾_1`：综合全通、高信誉原生家宽、测速达标。
- `🇹🇼 台湾_2_ISP`：商用双 ISP 或低分家宽。
- `🇹🇼 台湾_3_IPLC`：家宽兼专线，只留 `_IPLC`。
- `🇺🇸 ❇️Free美国_1_USAI_NF`：统一认定美国、AI 全通、Key 级前置。
- `🇺🇸 ✨️❇️美国_2_GOAI_NF_D+`：属地分歧但谷歌认定美国且 AI 全通。
- `🇸🇬 ❇️新加坡_2_Lnd`：新加坡链式落地。
