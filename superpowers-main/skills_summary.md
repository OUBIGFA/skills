# 小说项目技能总结 (Skills Summary)

本文档总结了 `novel/skills` 目录中各个技能的核心功能及其在开发流程中的作用。这些技能构建了一套完整的、基于 TDD 和子代理驱动的开发规范。

## 技能概览

| 技能名称 | 核心功能 | 作用与应用场景 |
| :--- | :--- | :--- |
| **using-superpowers** | 技能使用准则 | 强制要求在开始任何任务或响应前，先检查并调用适用的技能，确保持续遵循最佳实践。 |
| **brainstorming** | 创意与设计探索 | 在开始编码前，通过对话澄清用户意图，探索多种实现方案并确定最终设计规范。 |
| **writing-plans** | 编写实现计划 | 为复杂任务创建详细的分步实现计划，确保执行者（如子代理）有明确的指导和验证标准。 |
| **writing-skills** | 创建与维护技能 | 将 TDD 原则应用于文档编写。通过模拟压力场景验证技能的有效性，确保流程文档真正具备指导力。 |
| **using-git-worktrees** | 环境隔离 | 利用 Git 工作树为新功能或修复创建独立的开发环境，避免不同任务间的代码和上下文污染。 |
| **test-driven-development** | 测试驱动开发 (TDD) | 坚持“测试先行”，通过 红-绿-重构 循环确保代码质量，严禁在没有失败测试的情况下编写生产代码。 |
| **subagent-driven-development**| 子代理驱动开发 | 在当前会话中高效执行计划。每项任务分配独立子代理，并进行规范合规性和代码质量的双重审查。 |
| **executing-plans** | 计划执行流 | 适用于跨会话的任务执行，强调分批实施、持续验证以及在关键节点进行架构审查。 |
| **dispatching-parallel-agents** | 并行代理分发 | 当存在多个互不干扰的独立问题（如不同测试失败）时，通过并行分发多个代理来大幅提升调试效率。 |
| **systematic-debugging** | 系统化调试 | 严禁凭直觉修复。要求通过错误分析、复现和证据收集找到根本原因后，再进行针对性修复。 |
| **verification-before-completion**| 完成前验证 | 在声称工作完成或 Bug 修复之前，必须运行完整的验证命令并展示证据，确保结论的真实性。 |
| **requesting-code-review** | 发起代码审查 | 任务完成后，主动调动代码审查代理（code-reviewer）来捕捉潜在的设计缺陷或代码质量问题。 |
| **receiving-code-review** | 接收审查反馈 | 强调以技术严谨的态度对待反馈。在实施前先理解并验证建议，而不是盲目接受或进行社交性奉承。 |
| **finishing-a-development-branch**| 开发分支完结 | 在所有任务和测试通过后，引导用户完成本地合并、PR 创建或工作区清理等收尾工作。 |

---
*注：以上技能通过严密的流程衔接，共同确保了开发过程的透明度、可追溯性和极高的交付质量。*
